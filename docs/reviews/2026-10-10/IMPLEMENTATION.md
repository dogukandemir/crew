## Defects exposed by actual Live acceptance

The paid run exposed integration defects that simulated provider responses had missed. They are fixed in source and covered by regressions: provider SDK model normalization broke accounting; unescaped JSON in the planner template forced heuristic fallback; provider-default thinking truncated bounded planner output; a lone custom CrewAI system template was ignored; per-call stop markers were lost across the accounting wrapper, letting generated observations corrupt tool calls; councils could reset retry counts or weaken criteria; and a run with only some completed tasks was labelled successful. Planner failure now stops visibly, source-file publication avoids regenerating file content, and the harness requires actual artifacts before accepting completion.

The first partial paid attempt produced two verified artifacts; its historical status was recorded as completed by the old success condition and is **not accepted as a successful benchmark**. A later run produced all three required source files and the independent restricted-container checks passed: **10 generated unittests, 12 formula cases and 10 invalid-input cases**. That run's own test task still failed because approval waiting consumed retries and reassigned the worker; it was stopped with its evidence preserved.

Approval continuation is now fixed and covered by the real CrewAI loop: an approval-required tool result yields before another paid generation, preserves the worker and attempt count, parks the run, and resumes only the exact approved invocation. Decisions and continuation state commit atomically; explicit operator pauses are preserved; a concurrent worker wave cannot lose the continuation request. The final paid completion passed with this workflow.

One resumed worker executed the exact approved unittest command and published four files, but its evaluator rejected the publication criterion because the packet omitted names/source paths and tool receipts. The packet now includes application-recorded publication metadata and execution results, retains complete text for small multi-file deliverables, and avoids repeating superseded versions. Publications have immutable paths so a retry cannot corrupt an earlier file's recorded hash. The final run using these fixes completed one task in one execution attempt and passed all seven criteria. Engineering's subordinate allocation was raised from US$1.50 to US$2.50 inside the unchanged cumulative US$5 company/project caps; no ledger values were reset. Its incremental estimated cost was US$0.032236, bringing the series from US$3.593896 to **US$3.626132**. All four example downloads matched recorded hashes; the downloaded tests independently passed on Windows. The series required eight unsuccessful/partial attempts and reused generated source files; it is not a clean first-run benchmark. Full evidence: [LIVE-ACCEPTANCE.md](LIVE-ACCEPTANCE.md).
